# 自习室在线预订与管理系统实施方案（毕设版）

## 1. 项目定位
本项目面向高校/社区自习室场景，提供“座位可视化预约 + 到店扫码签到签退 + 运营管理 + 统计分析”的完整闭环。

目标是达到毕设可交付标准：
- 业务流程完整可演示
- 前后端分离、模块边界清晰
- 数据模型合理、可支撑核心功能
- 可在本地一键启动并完成端到端测试

## 2. 技术选型

### 2.1 后端（backend）
- Java 17
- Spring Boot 3.x
- Spring Web + Validation + Security（JWT）
- MyBatis-Plus
- MySQL 8.0
- Redis（可选：验证码、会话、提醒队列）
- Maven

### 2.2 前端
- Vue 3 + TypeScript
- Vite
- Vue Router + Pinia
- Element Plus
- Axios
- ECharts（统计图表）

工程拆分：
- `mobile-web`：用户端（移动优先）
- `admin-web`：管理端（后台运营）

### 2.3 运行环境
- JDK 17
- Node.js 20+
- MySQL 8.0
- Redis（可选）

## 3. 总体架构（前后端分离）

严格采用前后端分离：
- `backend/`：只放服务端代码、SQL、配置
- `mobile-web/`：只放用户端页面、状态管理、接口调用
- `admin-web/`：只放管理端页面、状态管理、接口调用
- `docs/`：方案、接口文档、部署说明

交互方式：
- 前端通过 REST API 调用后端
- 登录后使用 JWT 访问受保护接口
- 实时状态先采用“轮询 + 快速刷新”实现（毕设可控），后续可扩展 WebSocket

## 4. 功能范围（毕设最终版）

### 4.1 用户端
1. 注册登录（手机号+验证码，可先模拟验证码）
2. 自习室信息展示（位置、开放时间、设施、评分）
3. 座位可视化展示（普通/静音/插座；空闲/已预订/临时离开/关闭）
4. 按日期+时段（早/中/晚）预约选座
5. 预约成功生成凭证码（二维码内容）
6. 扫码签到/签退
7. 临时离开登记（保留 15 分钟）
8. 历史订单、违规记录、积分、优惠券、消息中心

### 4.2 管理端
1. 自习室与座位管理
2. 开放时间管理（工作日/节假日）
3. 预约规则配置（每天最多 2 次、单次 <= 4 小时、签到宽限 15 分钟）
4. 座位临时关闭/恢复
5. 举报处理（核实/驳回）
6. 统计报表（使用率、热门座位类型、月预约量、违规分布）

## 5. 关键业务规则
1. 每个用户每天最多预约 2 次
2. 单次预约不超过 4 小时（通过时段控制）
3. 开始后 15 分钟未签到，订单自动取消并释放座位
4. 临时离开最多保留 15 分钟，超时可记违规
5. 违规累计 3 次，限制预约 7 天

## 6. 数据库设计

### 6.1 核心表
- 用户与资料：`sys_user`、`user_profile`
- 自习室与座位：`study_room`、`room_open_rule`、`seat`
- 规则配置：`booking_rule`
- 时段占用：`seat_slot`（并发与状态控制核心表）
- 预约流程：`booking_order`、`checkin_record`、`temp_leave_record`
- 违规举报：`violation_record`、`violation_report`
- 评价通知：`review`、`notification`
- 积分优惠：`points_account`、`points_txn`、`coupon_template`、`user_coupon`
- 统计快照：`stats_daily`

### 6.2 关键约束与索引
1. `seat_slot(seat_id, booking_date, slot_code)` 唯一，防止同座位同时间段重复占用
2. `booking_order.order_no`、`voucher_code` 唯一
3. 按用户日期、房间日期时段建立组合索引，优化查询

## 7. 接口分层与模块划分

### 7.1 后端分层
- `controller`：请求入口
- `service`：业务编排与规则校验
- `mapper`：数据库访问
- `entity/dto/vo`：数据结构
- `config/security`：安全认证与跨域
- `job`：定时任务（超时取消、提醒）

### 7.2 前端模块
- `views/auth`：登录注册
- `views/room`：自习室与座位图
- `views/booking`：预约下单与凭证
- `views/checkin`：签到签退
- `views/user`：历史/积分/优惠券/消息
- `views/admin`：管理台与统计
- `api`：按领域拆分接口文件
- `stores`：用户态、消息未读数等

## 8. 开发里程碑

### 阶段 1：基础骨架
1. 初始化 backend/frontend 工程
2. 建库建表
3. 登录鉴权打通

### 阶段 2：核心闭环
1. 自习室与座位展示
2. 预约选座 + 凭证
3. 签到签退 + 临时离开 + 超时取消

### 阶段 3：运营与完善
1. 管理端规则和举报处理
2. 评价、消息、积分优惠券
3. 统计报表与导出

### 阶段 4：联调与答辩材料
1. 功能联调、异常场景验证
2. 演示账号与演示数据准备
3. 完成毕业设计文档与系统截图

## 9. 验收标准（毕设）
1. 前后端目录独立，能够分别启动
2. 核心流程可完整演示：预约 -> 签到 -> 临时离开 -> 签退
3. 管理员能配置规则并处理举报
4. 至少 4 个统计指标可视化展示
5. 提供数据库脚本与部署说明

## 10. 后续实现约定
1. 所有新增代码继续保持前后端分离，不跨目录混放
2. 接口统一前缀：`/api/v1`
3. 统一响应结构：`code/message/data`
4. 关键操作写入操作日志，便于答辩说明
